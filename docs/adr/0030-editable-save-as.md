# ADR-0030: 編集可能として別名保存（workspace 複製 + fingerprint 別個体）

- 日付: 2026-10-08
- ステータス: **実装済（実機確認待ち）**
- 関連: ADR-0007（fingerprint 索引）、ADR-0011（Save As で新ファイルへ切替）、ADR-0020（申請書テンプレ / form_field）、ADR-0026（戻せる確定 — 編集可能マスター）、HANDOVER §保存モデル（下書き／確定）

## Context

申請書テンプレ（ADR-0020）の実運用で 2 つの問題が報告された。

1. **フォーム入力して別名保存したあと、元のファイルを開くと別名側の記入内容が表示される。**
   記入値は `form_field` overlay の `properties.value` であり、overlay は **元 PDF の workspace** に属する。
   別名保存（確定 = 焼き込み）しても記入値は元タブに残り、そこで下書き保存（編集可能として上書き）
   すると元 workspace に永続化される。テンプレ A と記入済み B という「別文書」の概念が無かった。
2. **別名保存ではフォームが維持されない。** 別名保存は overlay があれば必ずラスタ再合成（焼き込み）で、
   出力ファイルにフォーム枠は残らない。フォームを保ったまま保存する手段は「上書き保存 → 下書き」
   （元 workspace のみ更新、ファイルは不変）しか無く、1 の事故と表裏一体だった。

制約: workspace は **元 PDF バイト列の SHA-256** で索引される（ADR-0007）。元 PDF をそのまま別名で
コピーすると fingerprint が一致して同じ workspace を共有し、1 と同じ事故になる。ADR-0026 で
「fingerprint 再登録（反映付き下書き）」は Dropbox 同期・複数台で紐づけが切れるため却下済み。

## Decision

**別名保存に「編集可能として保存」モードを追加する**（下書き保存の別名版）。

### 1. 「同じ見た目で fingerprint だけ違う PDF」を新ファイルとして書く

`src/backend/editable-copy-bytes.js` `makeDistinctPdfBytes`:
- mupdf の **増分保存 (incremental)** で Info 辞書に `/KPDF3EditableCopy <時刻 乱数>` を追記する。
  元バイト列は先頭からそのまま（前方一致）、末尾に小さな xref セクションが付くだけ。
  再シリアライズは起きず、PDF 仕様上まっとうな更新なので Adobe / Dropbox で警告が出ない。
- 失敗時（壊れた PDF）と **200MB 超**（β.134 サイドカー経路、mupdf OOM の前科）は
  `%%EOF` の後ろに PDF コメント 1 行を追記するフォールバック（リーダは末尾の余分な行を無視）。
- 書き出した新ファイル B.pdf は **元 PDF と見た目が同じ**。書き込みはファイルには乗らない
  （= 下書きと同じ）。あとで B を「上書き保存 → 確定保存」すれば焼き込まれる。

### 2. workspace を複製して新 fingerprint で登録

`src/domain/workspace-clone.js` `cloneWorkspaceAsEditableCopy`:
1. SQLite online backup（`db.backup`）で `.kpdf3` を複製（WAL 未チェックポイント分も含む）。
2. 複製の `source_pdf` を新バイト列に差し替え（`Workspace.replaceSourceBytes` — **pages テーブルは温存**
   なので回転・削除・並び順・挿入ページ・しおり・画像アセットがそのまま残る）。
3. 画面側の overlay スナップショット（未保存の記入値を含む）と未確定の削除を複製に反映。
4. 複製元の lineage（`predecessor`）・書き出し履歴・暗号化フラグは引き継がない（別文書）。

main `kpdf3:save-as-editable` が ①新バイト列を `savePath` に書き → ②複製 → ③registry に登録。
複製に失敗したら書いた PDF を消す（中途半端な PDF が残ると次に開いたとき空 workspace になり
「フォームが消えた」に見えるため）。**元 workspace には一切書き込まない。**

### 3. 元タブは「最後に保存した状態」に戻す（Word の Save As 流儀）

renderer `actionSaveAsEditable`: 複製後、元タブの projectStore を元 workspace の永続 overlay に
`reset`、未確定削除と undo 履歴をクリアしてから新タブで B を開く。今回の記入内容は B 側に移り、
元タブ A は最後に保存した状態（テンプレ）に戻る。**これが 1 の再発防止**（A を後から下書き保存
しても記入値は入らない）。元 workspace に永続済みの書き込み・ページ構造はそのまま。

### 4. 導線

- 「名前を付けて保存」ダイアログに、書き込みがあるときだけ 2 択ラジオを出す:
  - **確定して保存**（既定 = 従来動作）— 焼き込み、Adobe 等でも見える
  - **編集可能として保存** — フォーム枠・書き込みをそのまま持った新ファイル。新ファイルでも
    フォーム記入・下敷き印刷ができ、元ファイルは変更されない。焼き込まないので他アプリでは
    見えない（あとで確定保存で反映）、を補足文で明示。
  - 「編集可能」を選ぶとセキュア書き出し / 白黒チェックは灰色化（焼き込み時だけ意味がある）。
- ファイルメニューに「編集可能なまま名前を付けて保存...」を追加（同じダイアログをラジオ
  「編集可能」初期選択で開く）。
- 既定を「編集可能」にしない: 焼き込まれていない B をそのままメールで送る事故を避けるため、
  明示選択にする。ラジオの選択は永続化しない。

## Why この選択肢か

| 選択肢 | 採否 | 理由 |
|---|---|---|
| **A. 下書きの別名版（新バイト列 + workspace 複製）（採用）** | ✅ | 新ファイルを開いた瞬間からフォーム記入・下敷き印刷ができる。元 workspace 不変で 1 を構造的に防ぐ。保存コアは不変（追加経路のみ） |
| B. 焼き込み別名保存 + 複製を編集可能マスター (predecessor) として紐づけ | △ | Adobe で記入が見える利点はあるが、開くたびに「編集に戻す」が要り、ユーザーの「フォームが維持されない」という見え方が残る。下敷き印刷も戻してから |
| C. registry を (fingerprint, path) で二重キー化 | ❌ | ADR-0026 で却下したパス依存の再来（Dropbox 移動で切れる、Explorer コピーで共有） |
| D. 元バイト列をそのままコピー | ❌ | fingerprint 一致 = workspace 共有 = 1 と同じ事故 |

## Consequences

- **B.pdf の実体は元 PDF と同じ見た目**（書き込みは乗らない）。ステータスバーの「下書き」表示と
  ダイアログの補足文でこれを伝える。確定が要るときは B で「上書き保存 → 確定保存」。
- B は元 PDF 比で数百バイト大きい（増分セクション）。/Info に `KPDF3EditableCopy` が残る
  （セキュア書き出しの qpdf sanitize で消える）。
- 元タブの未保存編集は B へ移り A のタブからは消える（Word 流）。テンプレ自体を直していた場合は
  先に A を保存してから別名保存する運用（ダイアログの補足文「元のファイルは変更されません」）。
- 複製は overlay 差分だけでなく workspace 丸ごと（元 PDF バイト列も複製側に 1 つ持つ）。
  ADR-0026 の dedup 思想とは異なるが、別文書なので独立して持つのが正しい。
- 既存経路（確定別名保存 / byte-copy / 上書き / 戻せる確定 / 印刷 / 回転）は 1 バイトも変えていない。

## 検証

- `test/editable-copy-bytes.test.mjs`（node --test）: fingerprint 分離・前方一致・ページ数不変・
  フォールバック（サイズ上限 / 非 PDF）。
- `test/editable-copy-clone.test.mjs`（Electron ランナー）: 複製側に記入値・回転・削除・しおりが
  反映、新 fingerprint、lineage/履歴なし、**元 workspace が overlay・バイト列・fingerprint とも不変**、
  複製失敗時にファイルを残さない。
- 実機: テンプレ A を開く → 記入 → 名前を付けて保存 → 「編集可能として保存」→ B が新タブで
  開き記入済み・Tab 巡回可 → A のタブは空欄 → A を閉じて開き直しても空欄 → B を閉じて開き直すと
  記入済み → B で下敷き印刷 → B で確定保存すると Adobe で記入が見える。
